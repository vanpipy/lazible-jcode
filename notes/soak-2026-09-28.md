## Findings & fixes

### Bug 1: autonomous profile missing `ambient.visible = false` (critical)

**Symptom**: with ambient enabled in autonomous profile, the runner still runs in TUI mode.
spawning kitty and waiting for user interaction. The cycle never runs automatically.

**Root cause**: the base `config.toml` defaults to `ambient.visible = true` (jcode's design is
"headless uses inline / visible pops a terminal"). The autonomous profile never overrode it explicitly.

**Fix** (commit `383ec50`): added `visible = false` to autonomous.toml.

**Verification**: cycle #2 actually ran headless after the trigger (forced end within 0.5s, but runnable).

### Bug 2 (already fixed earlier): base config polluted via symlink (see symlink-incident.md)

### Observation: cycle #2 agent did not respond

**Symptom**: trigger → headless cycle starts → model produces no assistant messages →
"forced end after 2 attempts".

**Not a config issue**: it's an ambient system prompt / model availability / OpenRouter rate-limit issue.
The cycle framework itself works.

**Likely causes**:
- OpenRouter quota / rate limit
- Model choice (`anthropic/claude-sonnet-4` behaves oddly in cycle context)
- Ambient system prompt doesn't strongly guide the agent to call `end_ambient_cycle`

**Suggested next steps**:
- Read the full transcript at `~/.jcode/ambient/transcripts/2026-09-28-110400.json`
- Adjust the ambient provider / model in `config.providers`
- Strengthen the ambient system prompt to force the agent to call `end_ambient_cycle`

## Summary

✅ **The autonomous profile framework is usable**: live reload / symlink safety / drift check /
audit hook all verified.

⚠️ **End-to-end autonomous cycle execution is not yet verified**: the headless cycle was
forced-ended within 0.5s (model didn't respond). This shows the cycle pipeline works, but we need:

1. A stable model (avoid OpenRouter rate-limit windows)
2. Or strengthen the ambient system prompt so the agent must respond
3. Or configure an ambient-specific provider / model (lighter weight)

To rigorously verify autonomous execution later, we need to:
- Have the user session inactive (pause_on_active_session or offline)
- Wait for the scheduler to fire naturally (max 30 min)
- Or trigger by hand via `display.debug_socket=true` + `JCODE_DEBUG_CONTROL=1` + `jcode ambient trigger`
